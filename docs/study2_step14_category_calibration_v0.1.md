# Bounded category calibration v0.1

`step14-category-calibration/0.1.0` appends one clarification to the unchanged
current prospective instructions. Under the frozen identity/granularity policy,
failure to establish entity identity need not imply abstention: demonstrably
shared named technique, architecture or family concepts may support
`conceptual_similarity_only` without equating releases or trained instances.
`shared_reference_target_only` requires evidence of the same reference target,
not a common label. Entity identity requires the same referent at compatible
actual granularity; difference requires positive distinct-referent evidence.
Abstain when evidence substantiates none of the other four categories.
All specificity, class, role, locality and non-transitivity safeguards remain.
There are no label-specific instructions, target rates or identity approvals.

Sampling precedes responses: exclude all v1/v2 development/held-out units and
exact pairs, including v1's unused held-out. Choose four cross-family-containing
and four within-family-only units. In each scope greedily maximize uncovered
source-family combinations, density, recorded specificity, instance/generic-name
cues and named-technique/model class coverage; break ties by SHA-256 of
`[version, unitID]`. These are source metadata cues, not inferred correct identities.
Fewer than four available units per scope blocks preparation rather than silently
changing the sample. Record available and selected features and per-unit counts.
No response or recommendation participates in selection.

Fresh ignored output: `var/study2_step14/semantic-calibration/v3/`.
The adapter reuses native queue reconstruction, endpoint/pair audits, schema,
validator, model/settings, persistence and uncertain-outcome STOP behavior.
The saved `original` arm means **current prospective**; `prospective` means
**category revised**. This label mapping is explicit in preparation/sampling files;
existing report before/after comparisons use those arms. Exactly 16 new requests.
The changed verifier compares the new instruction suffix without weakening any
historical file hash guard. Historical modules are unchanged and pinned.
V1/v2 remain immutable evidence of earlier experiments, not evaluations of this
revision. No development requests are written or dispatched.

Commands using the research interpreter:
`python -m src.evaluation.step14_category_calibration prepare`, then `dry-run`
and `report`. The separately initiated researcher-only live gate is
`run-held-out --execute`; all accept `--root`. Preparation refuses overwrite.
Share sampling.json/md, preparation.json, manifest.json, and eventual report.json,
comparison.json and worksheet.json. The small stratified sample is not population
gold; category changes or fewer abstentions do not establish scientific improvement.
