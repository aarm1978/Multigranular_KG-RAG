# PROPOSED: Step 14 multigranular canonical alignment

2026-11-13. **Pending researcher review; not an approved policy or ontology amendment.** This proposal implements no identities, ontology edits, canonical allocation or production links. The scope/completion decision, identity/granularity policy, automatic-acceptance amendment, 29 exact pilot approvals and frozen Step 13 outputs retain their authority. No handoff milestone is advanced.

## Representation decision

Retain strict identity: the same scientific referent at compatible granularity, with existing evidence and provenance requirements. `consolidatesTo` (D-16) remains unchanged: `owl:Thing` to the existing union of ComputationalModel, Tool, Variable, Concept, HydrologicFeature, EvaluationMetric, Parameter and Algorithm. In particular its range does **not** currently include DatasetResource. This proposal does not silently extend that range or reinterpret strict identity.

Add, prospectively, **`ciroh:correspondsToBroaderReferent`**: an occurrence's specific referent is an explicitly supported realization/version of the named broader referent represented by the target. It is **not identity**, equality, collection membership, derivation or generic semantic similarity. It permits a version-specific NWM occurrence to correspond to a named NWM family anchor while preserving its original version, assertions and evidence. Two source occurrences linked to one anchor are not thereby identical. A family-level occurrence itself would use strict identity to its family anchor where supported; broader correspondence must not manufacture a narrower granularity for an unspecified mention.

Proposed domain and range: OWL union `(ComputationalModel, Tool, DatasetResource)` on each end. Operational validation additionally requires the same concrete supported class and a genuine broader/narrower referent relationship. Initial applicability is named model/product versions and named dataset-resource releases; trained instances, implementations, workflows and other families require explicit evidence and compatible class semantics, not blanket admission. Exclude geographic containment, persons/organizations, papers, repository branches/builds/deployments and architectural resemblance as automatic family support. `implementedBy` concerns a Repository; `hasModelVersion` has Repository domain; dataset `hasMember`/`isMemberOf` concerns collections. None represents this broader referent relation without a semantic change. A new property is therefore necessary for the proposed **graph** representation.

No new class is proposed. Anchors are instances of an existing appropriate concrete scientific class with explicit alignment-record granularity. If an existing class cannot legitimately describe a family referent, hold the case for the researcher rather than assigning a superclass, retyping an occurrence, or inventing a family class. Whether this restriction is sufficient is part of this representation gate.

| Alternative | Assessment |
|---|---|
| Reuse consolidatesTo / owl:sameAs | Reject: would weaken identity or equate distinct releases. |
| Reuse isMemberOf / broad external specialization property | Reject as default: collection semantics or imported entailments do not establish the intended alignment. |
| New relation plus alignment sidecar | Recommend: one additive property; no new domain entity class. |
| New alignment assertion class / full relation reification | Defer: unnecessary for the initial provenance-preserving implementation. |

The new property has **no transitivity, symmetry, functionality, inverse functionality, property chains, sameAs implication, inverse declaration, or subproperty relationship to consolidatesTo**. Absence of a transitivity axiom is not an OWL prohibition: application validators and query contracts must forbid closure-based inferred alignments. Sharing a target confers no equality, class substitution, or transfer of evidence. Contradictory versions may legitimately correspond to one family, but their version-specific evidence must stay attached to the original occurrence.

Use an immutable alignment sidecar with exact occurrence and anchor references, relation kind, source/target granularity, preserved version statements and their roles, source excerpts/offsets/hashes, policy revision, acceptance state, ambiguity flags and supersession references. No version role is inferred from a source capture hash. Neo4j can hold these references/qualifiers on the relationship. RDF/OWL uses the ordinary object-property triple plus a keyed sidecar (or an assertion-specific named graph in a provenance dataset); multiple evidentiary records for one triple remain separate. Qualifiers are validation metadata, not OWL axioms that authorize attribute inheritance. Do not assert ordinary RDF metadata *about the property definition* as if it qualified an individual assertion.

After approval only: update the master inventory and machine specification together; allocate a new property inventory ID; update alignment-record schema and validators; generate OWL with the existing `src/ontology/build_ontology.py` process, never edit generated OWL. Run focused signature, union-domain/range, qualifier, evidence-losslessness, no-equality/no-chain and deterministic-generation regressions. Run structural/import checks and the repository's researcher-confirmed Protégé/HermiT gate on the exact generated artifact, recording version/hash, consistency and zero unsatisfiable named classes. Include negative entailment checks demonstrating that shared targets do not imply sameAs. Do not run HermiT or regenerate anything in this proposal turn. Existing extraction contracts and Step 13/order-50 hashes remain frozen; a new ontology version and a separate alignment view must not rewrite their provenance.

## Offline implications preview

`step14_multigranular_preview` is an overlay on existing triage and automatic-acceptance outputs. It reuses their readers, hashes, exact memberships and evidence sidecars; it does not run either upstream consumer. Identity candidate scopes are the **pre-overlap eligible complete scopes**, retained as hypotheses, not newly accepted identities. Shared occurrences do not erase an individual candidate, but overlapping scopes are not unioned or mapped to one strict canonical ID. Historical approvals remain separately copied without extension.

The saved `v2-null-summary-fix/summary.json` reports **51,079 candidate scopes; 13,608 pre-overlap eligible scopes; 13,244 overlap-blocked scopes; 364 final disjoint provisional scopes**. The final count consists of 10 identifier-supported scopes (22 occurrences; 14 implied identity pairs, zero explicit semantic pairs) and 354 LLM-supported scopes (948 occurrences; 1,187 explicit pairs). The 13,608 and 364 counts describe different stages of the same saved membership-scope population, not candidate pairs or canonical families. No separate saved 360 result was located in the available baseline directory; do not replace 364 with that approximation. The terminal overlay verifies these definitions against saved rows rather than hardcoding the counts. The selected-pair population still contains 73,416 validated recommendations, 20 prior pair assessments, 609 prior group overlaps and six invalid comparisons. The full identifier/lexical and 237 ordinary unreviewed / 17 cross-family oversized accounting stays in the pinned baseline summary; all 25 oversized scopes remain separately retained without expansion.

Broader evidence recovery is intentionally narrow and **proposed**, not a new automatic production rule. For an already nominated pair in a supported exact class, use original labels and selected literal quotations. Require each source to explicitly state a named version/release or named family. A terminal numeric label suffix can identify the name to look for, but is not itself evidence. The name must appear with `version N`, `release N`, or `(model/software) family` in that occurrence's selected quotation. Abbreviation expansion requires a literal `Long Name (SHORT)` statement in the pair's source evidence. No embedding, positive LLM label, shared superclass or name equality alone supplies support. Contrastive, speculative, architecture/training, subset and derivation contexts are conservatively excluded by a documented literal screen. This screen is incomplete linguistic analysis, not proof of scientific identity; representative development examples require researcher scrutiny. Unsupported phrasing remains held, not rejected.

The overlay records a pair-local **anchor hypothesis**, not a global canonical ID. Equal spelling across hypotheses does not globally deduplicate scientific families. Thus the reported distinct anchor count is a count of proposed hypotheses, an upper-bound bookkeeping description rather than an estimate of unique families. A source naming multiple incompatible anchor descriptors holds that source's ambiguous links; independently supported links from other sources survive. Compatible overlapping links remain individually visible. Overlap components are diagnostic only and never become identity groups or family memberships. A named-family occurrence supports the anchor's referent but should ultimately link by strict identity; the preview preserves `qualifier=family` for the decision gate rather than pretending it is a narrower release.

Pair statuses are exclusive: broader-evidence candidate first, otherwise eligible exact candidate, otherwise held (including ambiguous-anchor bridges). `exactCandidate` separately preserves the original identity hypothesis, so its total overlaps the broader category and must not be added to it. Broader links with family-level source qualifiers are **anchor-support proposals**, not authorized assertions of the proposed narrower-to-broader property. All links retain exact evidence pointers and quoted text; no version-specific assertion is copied to another source. The terminal summary reports scopes, explicit pairs, unique occurrences, link hypotheses, class/family/scope strata, largest overlap components and ambiguous bridges. Examples are deterministic purposive development examples, never the confirmatory sample. Little or zero broader recovery is a valid result: selected excerpts may not affirm family/release structure. Full evidence remains recoverable through original bindings; this task does not rescan it or infer absent structure.

## Prospective metrics (declare before observing overlay yield)

Fix a versioned occurrence denominator `U`: accepted Step 13 source-local occurrences in the predeclared eligible alignment classes, with a documented crosswalk to the frozen snapshot. Report excluded classes and missing-provenance occurrences separately, and report both full and inventory-excluded baseline scopes; do not treat candidate-pool coverage as corpus coverage.

1. **Strict-identity consolidation ratio:** `( |U| - |P_strict| ) / |U|`, where `P_strict` is a validated disjoint partition into approved/policy-accepted strict identity groups plus singleton unresolved occurrences. No pairwise/component union or family link reduces this partition. The current overlapping preview cannot supply this metric.
2. **Broader/family consolidation ratio:** `( |U_b| - |P_family| ) / |U_b|` for a separately frozen family-eligible scope `U_b`. Only supported, unambiguous mappings to one appropriate family anchor count; unlinked/ambiguous occurrences remain singleton residuals. This is a **projection compression statistic**, not node deletion, identity accuracy or an improvement over the strict ratio. Report its denominator and coverage beside it; do not select among projection definitions after seeing yield. Pair-local anchor hypotheses in this preview are not sufficient to compute a production value.
3. **Cross-source canonical-link coverage:** unique occurrences in `U` with an accepted link to an anchor supported by at least two distinct authoritative source families, divided by `|U|`. Report strict and broader coverage separately plus their occurrence-set union; never sum overlapping link counts. Unresolved/unlinked occurrences stay in the denominator. A multiorigin occurrence alone is not independent cross-source corroboration. Intra-artifact and same-family/across-artifact coverage are separate strata.

Frozen order-50 graph size, isolation, density and richness remain unchanged. Report alignment-view metrics separately; a graph with added anchor nodes/edges is not directly comparable to that graph without a declared projection. No favorable numerator/denominator is selected from preview results.

## Minimal evaluation adaptation and decisions

Retain one independently assessed, model-blind 60/80/100-judgment budget after final policy/frame freeze. Stratify by **strict identity versus broader correspondence**, then the existing route/scope/size risks, collapsing small strata by a predeclared rule. Document `pi=n_h/N_h` and weights `1/pi`; report category-specific correctness, never pooled “identity precision” for nonidentity links. Complete-group consistency remains the strict judgment; a broader judgment checks the entire bounded anchor-support set, the explicit source-to-family relationship and no evidence transfer across releases. Reject/hold unsupported specificity; distinguish correct common-family support from strict equality. Preserve the existing finite-population weighting and nonresponse/undetermined bounds. Group sampling, not independent sampling of correlated links, is preferred; report link-weighted estimates only with explicit design weights. Freeze scientifically deduplicated anchors before sampling: pair-local duplicate hypotheses are not a suitable confirmatory frame. Purposive risky overlaps stay outside probability estimates. No sample is selected here and no repeated tuning/review rounds are authorized.

## PROPOSED v2 development correction (2026-11-13)

This remains unfrozen development work, not ontology approval. Researcher-reported v1 baseline: 13,608 eligible groups / 4,231 distinct occurrences, 364 disjoint provisional groups, 604 overlap components; 19 broader pairs / 27 occurrences, only seven occurrences beyond exact eligibility; zero cross-family broader pairs and zero generic support links. Sixteen broader pairs had equal explicit versions and three had different versions. These are distinct denominators, not interchangeable consolidation results.

Bounded saved examples inspected for this correction include NWM 2.0 versus 1.2, GMET 2.0 versus 2.0, and repeated NCL 6.4.0 evidence. Equal-version support is no longer interpretable as newly established different-version correspondence. Cross-family NextGen excerpts concern binaries/ecosystem context, and Singularity excerpts concern containers; neither supplies the required shared broader scientific referent. They remain held rather than receiving NWM or product-family membership by association. Generic support is now permitted for an affirmative, source-bound definition such as `NAME is a hydrologic model`, with the same explicit alias expansion and version counterpart requirements. A generic definition is support for a candidate anchor, not proof of family-level granularity. Speculative/contrastive and architecture/instance contexts remain excluded. No LLM text or untyped capture-version dictionary supplies affirmative evidence.

Strict candidacy remains the independent `exactCandidate` property. Broader support separately reports `generic_to_version`, `equal_version`, and `different_versions`; its scope/class/mechanism strata include unsupported cases. Examples are development illustrations only. The expanded grammar is still deliberately incomplete, and no authentic v2 yield is claimed before execution.

Candidate anchors may now be shared across a deterministic star of compatible pairs only when every pair contains the **same exact occurrence with identical literal evidence binding and the same class/name/granularity descriptor**. Select the most-supported witness first, breaking ties by stable witness tuple; remove only those assigned pair hypotheses, then repeat. Strings alone never merge anchors. A-B and B-C may share the B witness; C-D cannot join that anchor without B support. This is a conservative, order-declared reconciliation strategy, not global scientific anchor uniqueness or transitive identity. Incompatible descriptor bridges remain held at the affected occurrence. Original approvals and original groups are untouched. Anchor and coverage counts include hypotheses, not approved mappings; groups contained in an anchor's supported membership are counted descriptively without approving them. Alternative star choices and unresolved homonyms remain researcher decisions.

The terminal run reports independent version-comparison counts, correspondence scope/class/mechanism strata, candidate anchor memberships and witnesses, groups contained in supported anchors, exact-eligible occurrences covered by anchors, and broader-covered occurrences beyond exact eligibility. Before/after comparison must use these fields alongside the v1 baseline above. There is no confirmatory sample or production graph write.
